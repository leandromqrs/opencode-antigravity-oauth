# Native OpenCode V2 adapter: offline only

## Delivered boundary

`./offline-opencode` exports `createOfflineModel(config): LanguageModel`. It is a real native OpenCode V2 route over `inferOffline`, not an AI SDK V1 `doGenerate`/`doStream` imitation. The actual SDK's `make().generate` aggregates the emitted events and `make().stream` exposes them. Both are covered by focused tests. This original slice did not include a root plugin or OAuth/provider lifecycle; the implemented root, restricted HTTPS transport and native OAuth continuation now supersede that boundary in `CONFIGURED-INTEGRATION.md`. Discovery/quota remain outside the text-only minimum; live authorization/entitlement are not verified.

Required configuration: caller-owned `provider`, `model`, `project`, `requestId`, injected `transport`, `textSemantics: 'delta' | 'cumulative'`, and `usageSemantics: 'single-report' | 'cumulative-snapshot'`. No actual service model/endpoint/account is inferred. Identifiers are bounded printable strings; configuration is validated and copied at construction. Its prototype must be Object.prototype; unknown keys, symbols and accessors fail. A fixed-string request ID is explicit **synthetic fixture configuration**; a supplied SDK request.id must match it. The configured integration continuation additionally permits a `requestId` factory, evaluated at lowering when the SDK has not supplied an ID, with the resulting value validated by the existing request serializer. See `CONFIGURED-INTEGRATION.md` for the configurable OAuth/native-provider lifecycle and its separate live evidence.

The route deliberately has no baseURL. Its endpoint path `/offline-only` is an unused structural Route field: injected transport.prepare returns the lowered input without rendering a URL or resolving auth; execute never calls runtime.http. `LanguageModel.make` supports this; `route.model` would require a baseURL, so it is not used. No artificial destination is added just to satisfy that convenience method.

## Actual contract sources

The official V2 server-plugin URL was fetched: https://opencode.ai/v2/docs/build/plugins/server redirects to https://opencode.ai/docs/build/plugins/server. It establishes registration/package loading, not custom driver construction; this work does not infer a V1 contract from the redirected page. Context7's `/anomalyco/opencode` query returned the official `packages/ai/README.md`: `Route.make`, protocol/body/stream separation, `LanguageModel.make`, and native Promise `make().generate/stream` usage.

The decisive source is the public installed **@opencode/ai 2.2.5** declarations and implementation, also inspected in the read-only Qwen sibling before installation here:

1. `dist/route/{client,protocol}.d.ts` and `client.js`: `Route.make` accepts a custom Transport; Protocol.body.from lowers LLMRequest; stream.step emits native LLMEvents. `prepareRequest` normalizes requests before lowering; compile then calls the custom prepare/execute methods. Both generation and streaming run the same route. The native adapter's protocol is an identity step over schema-validated native events produced by the injected transport pipeline.
2. `dist/route/transport/index.d.ts`: execute returns a scoped Effect of `{frames: Stream<Frame, AIError>}`. The implementation uses `Effect.acquireRelease` for its controller and `Stream.fromAsyncIterable` over the offline pipeline. Scoped abort interrupts pending reads and triggers the existing iterator cleanup.
3. `dist/schema/{messages,options,events,errors}.{d.ts,js}`: native LanguageModel, LLMRequest, Message, GenerationOptions, LLMEvent/Usage and AIError contracts. Text events have start/delta/end IDs; finish events carry normalized/raw reasons and **optional** usage. Usage's own fields are optional; no mandatory sentinel exists here. Schema.toType(LLMEvent) validates the already-decoded native frames rather than attempting to decode branded IDs/classes from a guessed wire representation.
4. `dist/index.js` and `llm.js`: the Promise API dispatches the real native route; SDK generate reduces streamed events. SDK RunOptions.signal cancellation rejects with the caller's original signal.reason. That SDK-owned behavior is not changed by this adapter; adapter-created input/output errors contain only fixed messages, no remote body/cause/prompt/abort reason. A generated SDK error may carry `partial` output already delivered; this is not a promise to redact generated user-visible text.

## Explicit local semantics

- **Text:** `delta` appends the concatenated text parts of each candidate chunk. `cumulative` treats those parts together as one whole-text snapshot and emits only its suffix. Equal snapshots emit no delta; non-prefix revisions fail. A terminal candidate without parts leaves previous text unchanged. There is no policy auto-detection. This is caller-selected synthetic behavior, **not evidence of upstream aggregation semantics**. Per-call state is isolated and normalized output is capped at 1 MiB in addition to the inference pipeline limits.
- **Usage:** `single-report` accepts at most one usageMetadata object, including an empty object or usage-only trailer. The later explicit `cumulative-snapshot` policy accepts repeated reports only when previously present counters remain present and nondecreasing; it uses the last exact snapshot without sums or merged fields. The local configured mode selects this policy; `single-report` remains available. See `CONFIGURED-INTEGRATION.md` for its source and limits. promptTokenCount maps to SDK inputTokens and totalTokenCount to totalTokens only when present. Every recovered usage counter is retained under `usage.providerMetadata.offlineInference`. Output/cache/thought counters are deliberately **not normalized**: candidatesTokenCount inclusion of thought/tool tokens is not established. Missing values remain absent, explicit zero remains zero; neither total nor output is synthesized. The SDK Usage.visibleOutputTokens getter itself falls back to zero; this adapter does not use it or populate outputTokens with that fallback.
- **Completion:** STOP → stop, MAX_TOKENS → length, safety/recitation/blocklist/prohibited/SPII/model-armor reasons → content-filter; remaining reasons → unknown, always preserving raw. CONTINUATION is not STOP or an implemented resume. text-end, step-finish and finish are emitted only after clean transport EOF and the existing explicit-finish policy, allowing usage trailers/errors to be read first. Content may have streamed before a later failure, but no successful terminal event is emitted on that failure.
- **Subset:** user/assistant text messages, text system instruction, generation.temperature/topP/maxTokens/stop. Tools, toolChoice, reasoning/signatures, media, message/part cache/metadata/native hints, provider options, request cache/metadata/raw modes, HTTP overrides, unsupported generation controls and structured generation are rejected when presented to lowering. All output parts must have only text, including rejection of thought:false rather than silently dropping it. The underlying pure inference module still supports its broader recovered subset; the native adapter deliberately does not claim that broader mapping.
- **Validation boundary:** the public SDK constructs/normalizes canonical LLMRequest before protocol lowering, including tool-history normalization and Unicode sanitization. The adapter validates what that boundary supplies; it cannot reject arbitrary keys already stripped by the SDK, or promise byte-identical preservation of pre-normalized input. There is no separate guessed public request wrapper. Custom JavaScript transport code remains caller-owned/trusted and can perform its own I/O; no such implementation is supplied or invoked in the fixtures.

## Dependency and compiler boundary

The initial adapter slice used project-local exact SDK dev dependencies/optional peers. The completed root integration now declares exact runtime dependencies `@opencode/plugin@2.2.5`, `@opencode/ai@2.2.5` and `effect@4.0.6`; no SDK migration was retained. The pure offline subpaths do not import these dependencies. `package-lock.json` records the graph. Installation used `--ignore-scripts`; no global packages/configuration were changed. The package root now exports the native server plugin; importing it or calling setup does not initiate login or inference.

**Known upstream declaration incompatibility:** SDK 2.2.5 fails `exactOptionalPropertyTypes:true` in its own image/media and events declarations (for example events.d.ts step/finish `{usage?: Usage | undefined}` fails a `{usage?: Usage}` generic constraint). No adapter implementation can fix those declarations. Public SDK 2.3.0/effect 4.1.0 was also checked locally: its events declarations still fail the same constraint and its request shape changes (generation no longer exists). It was not retained; the final lock is 2.2.5/4.0.6 only.

The original `tsconfig.json` keeps **all original strict flags**, including exactOptionalPropertyTypes, and excludes the native adapter, configured modules and server entrypoint. `tsconfig.opencode.json` separately compiles those SDK-dependent files with exactOptionalPropertyTypes:false; strict/noUnused/noUncheckedIndexedAccess and declaration checking remain enabled. Both build/typecheck scripts execute both configurations. There is no skipLibCheck, @ts-ignore, test deletion, node_modules patch or weakened setting for original source. This is an explicit, narrow SDK compatibility exception, **not a claim the native source has passed exactOptionalPropertyTypes:true**. Strict consumers face the same upstream limitation; the parent retains final review ownership.

Audit chronology matters: the original adapter graph reported **5 moderate findings** through rimraf/gaxios/gcp-metadata. The dependency-only correction retained `gcp-metadata@8.1.4` and overrode its gaxios to `7.1.4`, removing that rimraf chain; `/tmp/opencode/antigravity-audit-after.json` records **zero findings** for that corrected snapshot. The override remains intact. Adding the required plugin SDK subsequently expanded the graph: `/tmp/opencode/antigravity-integration-audit-final.json` and `/tmp/opencode/antigravity-rea/final-release-audit.json` each record **21 moderate, zero high and zero critical findings**. The earlier zero-finding snapshot is not evidence that this larger graph is clean. No incompatible SDK/dependency major was forced to silence those findings. The parent owns final graph reachability review and separate checkout/packed-consumer audits; consumers do not inherit root overrides automatically.

## Verification ownership

Run with the project's Node environment:

```sh
npm run build
npm run typecheck
node --test test/offline-opencode.test.mjs
npm run demo:opencode
```

The original suite imports the compiled named package subpath and actual public SDK, exercises generate/stream, validates events with LLMEvent schema, traps global fetch, verifies request body/system/generation conversion, explicit delta/cumulative behavior, usage absent/zero/partial/duplicate cases, unsupported input/output, raw finish reasons, failures/EOF, pending-read abort, consumer-break cleanup, concurrent fragmented streams and configuration snapshots. The later root continuation replaces obsolete root-rejection assertions with inert native-root tests; the decoder also fixes transport coalescing without weakening per-frame/total limits. Initial missing-module RED was observed; later identity/config regressions also failed before their fixes. The parent owns final complete-suite and integration review, especially the compiler exception and lockfile.

The runnable demo uses only in-memory synthetic frames and prints native generation/events. It does not demonstrate a service call, authorized consumer OAuth integration, entitlement or an activated OpenCode plugin. The native adapter is ready for **offline review**, not live use or publication.
