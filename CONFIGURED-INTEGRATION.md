# Text-only native OpenCode V2 integration

## Entry points

The package root exports a real default `Plugin.define` server plugin. Its `setup(ctx)` reads the explicit public configuration from `ctx.options`, validates it against the immutable production destination policy, and registers native OAuth/provider hooks. The explicit `agy-public-oauth` and `agy-local-oauth` modes register OAuth only. Import and setup never start authorization, exchange tokens, read the installed binary or credential files, activate connections or perform inference. Missing/invalid options fail with a sanitized configuration error, not simulated success. The fetch wrapper is constructed during setup but invoked only by explicit OAuth completion/refresh or inference.

`./configured-plugin` exports `createAntigravityPlugin(configuration, { fetch, now? })` for explicit production construction and `createSyntheticAntigravityPlugin(...)` solely for isolated fake-fetch tests/demos. The synthetic factory requires reserved `.invalid`/`.example` destination hosts and explicit injected fetch. It cannot configure a Google destination. The production factory/root cannot opt into the synthetic policy or expand its reviewed destinations. No transport, endpoint, policy or client-secret override is accepted through root options.

## Experimental public-client login only

The package root accepts exactly `{ "mode": "agy-public-oauth", "authorizationAcknowledged": true }` to register the `agy-public-oauth` integration and its `configured-pkce` OAuth method. No client registration, project or model metadata is required from the operator. This mode registers no provider transform, inference runtime or model inventory. It performs no catalogue, quota, subscription, billing or entitlement discovery. Completing login would only save a native OAuth credential through OpenCode; it would not enable generation or prove service access.

This is a secretless candidate, not a verified working Google login. It uses the public consumer ClientID `1071006060591-tmhssin2h21lcre235vtolojh4g403ep.apps.googleusercontent.com`, recovered from ClientID field construction in installed agy SHA-256 `9db59b6371107b939befa9c507c0a24989fda974e75d81d8529f3689ef7322e5`. The shipped client sends a nonempty secret; this public mode never reads it. A parent-owned anonymous synthetic-code probe returned HTTP 400 `invalid_request`, classified without printing its description as requiring a client secret. That supports adding the separately authorized local mode below, not claiming successful login. The FAQ permission warning still applies.

The preset fixes the existing production issuer, v2 authorization endpoint, token endpoint and HTTPS callback. It requests only the five currently proven base scopes: `https://www.googleapis.com/auth/cloud-platform`, `userinfo.email`, `userinfo.profile`, `cclog` and `experimentsandconfigs` (each abbreviated scope uses the same `https://www.googleapis.com/auth/` prefix). This is an explicit candidate scope set, not a claim that the complete native consumer scope set or live service requirements were recovered. `openid` and `aicode` are not silently added. Options cannot override scopes, endpoints, namespace, client identity or add a secret.

### Configure OpenCode V2 locally

Build this checkout with `npm run build`. Merge this entry into the project's `opencode.jsonc` `plugins` array, preserving unrelated entries and replacing the example path with the absolute checkout directory:

The same configuration is provided in [`examples/opencode-agy-public.jsonc`](examples/opencode-agy-public.jsonc). It is an inert, packaged example, not an active project configuration. Loading the explicit experimental public-client preset performs no automatic HTTP; Google acceptance remains unverified.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "/absolute/path/opencode-antigravity-oauth",
      "options": {
        "mode": "agy-public-oauth",
        "authorizationAcknowledged": true
      }
    }
  ]
}
```

This uses the V2 `plugins`/`package`/`options` shape, not V1 `plugin` syntax. The official [V2 plugin guide](https://opencode.ai/v2/docs/build/plugins) documents local package directories and `ctx.options`; the [V2 provider CLI guide](https://opencode.ai/v2/docs/cli/providers) documents `/connect` and `auth login`. The V2 URLs currently redirect to the corresponding unprefixed native V2 pages.

Saving configuration only loads the integration; it does not start consent. If authorized to attempt the experimental flow, the operator can select **Antigravity public OAuth (experimental, login only)** under `/connect`, or run in an interactive terminal:

```sh
opencode auth login agy-public-oauth --method configured-pkce
```

Follow OpenCode's authorization prompt, copy the code displayed on the Antigravity callback page, and paste that code into OpenCode. It is an OAuth authorization code, not an access or refresh token. The current page can remove query parameters from its address bar, so copying that URL is not required and may not contain the code. Do not put the code in logs or chat. After updating/reloading the plugin, start a fresh login rather than reusing a failed attempt's code. The registered redirect remains `https://antigravity.google/oauth-callback`; this page-copy mechanism is not the deprecated `urn:ietf:wg:oauth:2.0:oob` redirect flow. No browser, authentication command, service request or user configuration was executed/changed during this fix.

Bare-code acceptance is restricted to the explicit `agy-public-oauth` and `agy-local-oauth` modes. They accept 1–2048 printable non-whitespace ASCII characters after trimming outer clipboard spaces, tabs and line endings, with an 8192-character raw-input bound. Internal whitespace, controls, non-ASCII, empty and oversized values fail before HTTP. URI-shaped input instead goes through the existing strict full-callback validator: a URL missing code/state or using another destination cannot be treated as a bare code. A valid full callback remains optional.

**Security trade-off:** a pasted code alone contains no returned state, so that path cannot check returned state locally. The plugin does not fabricate a callback or substitute its expected state and claim it was verified. Authorization still sends fresh random state and a unique PKCE-S256 challenge; exchange sends the pasted code, original registered redirect and that transaction's verifier. Cross-transaction code/verifier binding depends on the token server's PKCE enforcement. Five-minute expiry, single-use, duplicate-winner protection, selected-account fences, cancellation and host-owned persistence remain enforced. Full-URL submissions still validate returned state; existing complete configured mode and the pure workbench continue requiring the full callback.

In public mode, both authorization-code and refresh requests omit `client_secret` and HTTP client authentication. Public-mode failures preserve typed, fixed-value diagnostics across catch boundaries, without forwarding descriptions, credentials or response bodies. `invalid_client` retains the wording `Public OAuth client rejected (invalid_client); secretless compatibility is unverified`, followed by safe diagnostic fields. That error alone does not prove that supplying a secret would resolve the rejection. There is no fallback to an embedded secret, different client, API key or ACP.

### Public-mode failure diagnostics

Both explicit presets add diagnostic fields; the local preset uses the prefix `Local OAuth diagnostic:`. Complete configured/synthetic mode keeps its generic error contract. The safe error message contains a fixed `stage`, fixed `reason`, optional numeric `http_status` and optional allowlisted `oauth_error`. No original exception/cause, request/response body, unexpected field name, remote description, URL, header, code, state, verifier, token, client secret or account identity is attached or logged by this patch.

The five stages distinguish `authorization_input` (invalid pasted input), `token_request` (`network`, `timeout` or `aborted`), `token_response` (HTTP rejection/redirect/destination), `response_read` (`body` or `json`, including unreadable or oversized data), and `token_validation` (fixed schema/field-validation reason). An `unsupported_response_fields` reason reports only that the strict response allowlist rejected something; it never identifies the remote field. Validation policy, scopes, client authentication and PKCE behavior are unchanged.

Non-success token responses are still rejected. Public-mode error JSON is read only from the exact token endpoint, bounded to the existing 64 KiB/30 seconds; redirects are never followed or parsed for remote details. JSON OAuth errors map only to `invalid_client`, `invalid_grant`, `invalid_request`, `unauthorized_client`, `unsupported_grant_type`, `invalid_scope`, `access_denied`, `temporarily_unavailable`, `server_error`, or `unknown`. Unreadable/malformed error bodies report `response_read` with the status when available, not an invented OAuth error.

Examples of safe messages:

```text
Public OAuth diagnostic: stage=token_response reason=http_error http_status=400 oauth_error=invalid_grant
Public OAuth diagnostic: stage=token_validation reason=unsupported_response_fields http_status=200
Public OAuth diagnostic: stage=token_request reason=network
Public OAuth client rejected (invalid_client); secretless compatibility is unverified; stage=token_response reason=http_error http_status=401 oauth_error=invalid_client
```

The native host may still show HTTP 500 in its UI. That host status is not the upstream token status. After parent validation/reload, one fresh user-operated attempt can establish the next failure stage: the parent should extract only the fixed diagnostic message (matching `stage=`) from its server error log, not share whole log lines/context or enable raw HTTP tracing. This instrumentation does not fix or establish the live root cause, and no live attempt was performed to test it.

The named `createPublicAntigravityOAuthPlugin(options, { fetch, now? })` factory is available from `./configured-plugin` for injected-fetch construction; `createAntigravityPlugin` and the root dispatch the same explicit mode. The synthetic factory does not accept it. Existing complete configurations remain strict and unchanged, including their exact credential-binding hash. Missing inference/models without the explicit mode is still invalid. Public-mode credentials use a separate mode/integration/OAuth binding and cannot be treated as configured inference credentials. PKCE, random request state, single-use/expiry, account fences, strict Bearer response validation, discarded ID tokens and host-owned persistence apply in both modes; returned-state validation requires a full callback, not a bare code.

The provider's registered file URL exports native `model(modelID, settings): LanguageModel`. Native `ctx.integration.transform` registers authorization/refresh; `ctx.provider.transform` publishes model metadata with the selected OAuth `sourceConnection`. No selected OAuth credential means no published inventory. No V1 driver shim, API-key fallback or ACP substitution is present.

## Explicit approved local-client OAuth and model discovery

Use exactly `{ "mode": "agy-local-oauth", "authorizationAcknowledged": true }` as the root plugin options, after explicit authorization to use the AGY application's complete OAuth client configuration. This mode does not depend on an installed AGY executable. The integration ID is `agy-local-oauth` and method ID `configured-pkce`; these identifiers and the existing credential binding remain unchanged for compatibility. The display name is **Google Antigravity**. The named `createLocalAntigravityOAuthPlugin` factory is also available from `./configured-plugin`. Public and complete modes never fall back to this mode, and its credentials have a separate mode/integration/OAuth binding with no secret in the hash.

After explicit user approval, this local mode requests `https://www.googleapis.com/auth/aicode` and `openid` in addition to the five base scopes. These additions match the recovered consumer scope composition (`getScopesByAuthMethod`, `0xa11c714..0xa11c832`; retained evidence: `displayed-code-investigation.md`). The public preset still requests only its original five scopes, and complete operator-owned configurations are unchanged. This is a consented compatibility test, not a diagnosis: the observed catalog HTTP 403 `PERMISSION_DENIED` did not identify insufficient scopes, and reauthorization may not resolve it. Local discovery can make the state-changing onboarding request described below; it does not request a subscription, purchase or credit fallback.

The added local scopes change its credential binding, so an existing five-scope credential cannot be reused or refreshed under the new configuration. The integration/method IDs remain unchanged. Authorize again using **Google Antigravity** and consent to the updated scopes; old-binding discovery/refresh stops before any request with `stage=credential_binding reason=reauthorization_required`. Existing host-owned credentials are not deleted or rewritten by this migration. When a token response includes `scope`, every requested scope must be present; omitted `scope` retains the existing validation policy.

The public consumer client ID, fixed Google destinations, callback and displayed-code instructions remain unchanged. Copy the page's displayed code, not its stripped address-bar URL. Returned-state validation remains impossible for a bare code; PKCE, five-minute expiry, one-use, duplicate-winner protection, account fences and host-owned token persistence remain enforced. Without an active native OAuth credential, setup does not resolve credentials, call discovery or publish a provider. The public secretless preset remains login-only.

With an active native OAuth credential, asynchronous discovery resolves it through OpenCode outside the synchronous provider transform and posts to `https://daily-cloudcode-pa.googleapis.com/v1internal:loadCodeAssist` with `{"metadata":{"ideType":9}}`. The transform only publishes prepared inventory with its source connection; credential changes trigger reconciliation and provider reload. An asynchronous transform is not supported by the V2 SDK, even though TypeScript accepts a Promise-returning function for a void callback. If the response has no project or current tier and exactly one default allowed tier whose ID is `free-tier`, discovery can POST `:onboardUser` with that tier and metadata. This is a **state-changing operation**, not a read-only metadata lookup. Validation-required eligibility blocks it; no default, multiple defaults or a non-free default do not trigger it. A pending operation is polled at most five times at five-second intervals using a strictly validated relative operation name. Failure or timeout does not roll back onboarding. A completed response must supply a valid project ID. See [`FINDINGS-configured-onboarding.md`](FINDINGS-configured-onboarding.md).

Discovery then calls `:fetchAvailableModels` with the returned or onboarded project, or omits the project if none exists. An explicitly empty or invalid project, project validation errors and top-level error envelopes fail closed. Requests reject redirects, have 2 MiB response and 30-second per-request bounds, and share a 60-second discovery deadline. Diagnostics exclude raw responses and credentials. The selected-account guard runs around onboarding and polls, but cannot make an external POST atomic with an account switch: the previous account may still be onboarded after the last check; a later fence prevents publishing its result under the new selection, not the remote side effect.

The native provider ID is `antigravity-local`. Models use the exact returned map keys, display names (or ID as display fallback), positive `maxTokens`/`maxOutputTokens` limits and `disabled` state. Candidate IDs must appear in `agentModelSorts` or `defaultAgentModelId`; explicit image-generation/audio-transcription IDs are excluded even if grouped as agents. If both agent grouping and default are absent, no models are guessed from names or general catalogue membership. Invalid/missing limits and other excluded models are counted in `catalogExcludedModels`; no usable candidates produces a sanitized diagnostic. `cost: []` means unknown prices, not free service. Capabilities advertise text input/output and the experimental tool-call adapter, not richer media capabilities or verified remote tool execution.

Effort variants: catalogue keys that end in a recognized effort suffix (`-minimal`, `-low`, `-medium`, `-high`) are grouped into one model per base ID with one variant per available effort, so `gemini-3.8-flash-low/-medium/-high` publish as `gemini-3.8-flash` with variants `low`, `medium`, `high`; no absent effort is invented. Grouping changes presentation only: `catalogExcludedModels` is still counted from the flat pre-grouping entries, the base model's default variant is chosen as `medium`, then `high`, `low`, `minimal`, and a plain entry that collides with a grouped base ID is superseded by the group. Each variant carries the exact original catalogue key in `settings.antigravityModel`; the host merges the selected variant's settings into the model settings, and the driver uses that wire ID only when it belongs to that base model's own default or variant set. Any other wire ID, including one borrowed from a different model, fails closed. Models without variants keep their own ID as the wire ID. Static fallback uses the same grouped shape. Grouped publication and driver resolution have synthetic coverage and stateless low/medium live acceptance; full-session generation remains blocked as described below.

Discovery is single-flight per selected credential with a 60-second successful-inventory cache, shortened to credential expiry. A static fallback inventory is cached for 30 seconds. Sanitized discovery failures have a 30-second per-connection cooldown. Credential and integration events reconcile captured inputs; an unreferenced five-second timer provides a fallback and retries discovery only after the inventory or failure cooldown expires. The synchronous transform performs no network or credential operations. Changed snapshots invalidate providers through `provider.reload()`, and plugin reload clears both caches. Cleanup aborts discovery and the event stream, clears the timer and prevents late publication. Selection is rechecked after credential resolution, service requests and before publication; late account-A results cannot publish under account B. Every inference dispatch resolves and validates the same captured native connection again.

Project validation failures report `eligibility_source=projectValidationError`. Diagnostics expose only a validated numeric `project_status` (0–16) and deduplicated, fixed enum names in `ineligible_reasons`; numeric enum inputs 0–12 normalize to those same recovered names. Raw messages, tier IDs/names, projects, bodies and credential values are never included. The recovered load schema separates repeated `ineligibleTiers` with tier IDs from `allowedTiers`, `currentTier`, `paidTier` and `g1Tier`; per-tier `UNSUPPORTED_CLIENT` metadata alone is not treated as global catalog denial, even without a current/paid tier. Successful load metadata therefore proceeds to the read-only catalog request, whose actual HTTP/error result remains authoritative. A top-level error envelope on HTTP success is rejected as `schema`, not accepted as metadata. No enrollment, generation entitlement or scope change is inferred from tier metadata.

Error envelopes expose `service_reason` from a detail whose `@type` is exactly `type.googleapis.com/google.rpc.ErrorInfo`. Allowed values are `ACCESS_TOKEN_SCOPE_INSUFFICIENT`, `SERVICE_DISABLED`, `CONSUMER_INVALID`, `ACCESS_DENIED`, `IAM_PERMISSION_DENIED` and `SECURITY_POLICY_VIOLATED`; other or missing reason values in that detail become `unknown`. Without a matching standard detail, a non-success HTTP response may classify only the exact message `Request had insufficient authentication scopes`, with an optional final period, as `ACCESS_TOKEN_SCOPE_INSUFFICIENT`; other messages leave the field omitted. Standard details take precedence. Domains, metadata, scope strings, service/project identifiers, messages and raw details are not retained in diagnostics. The sanitized reason survives the failure cooldown when discovery fails; scope changes are not automatic.

Only a local-mode `fetchAvailableModels` HTTP 403 activates the static fallback (`src/configured-plugin.ts:125-137`). Other stages, statuses and schema failures do not. Its five model IDs and context/output limits are local estimates, not service-returned catalog data or evidence of entitlement; names explicitly label them as estimates and `cost: []` remains unknown. If discovery resolved a valid project before the 403, the fallback preserves it for generation via private error-associated context, after rechecking the selected account; it does not include the project in diagnostics. If no project was resolved, generation remains projectless. Neither fallback publication nor a model ID establishes successful inference.

Projectless catalogue entries can remain visible, and the experimental driver omits `project` from generation JSON when discovery did not return one. It does not invent a project; manually configured projects remain required and validated. Remote acceptance of projectless generation has not been proven. The driver uses the fixed daily `:streamGenerateContent?alt=sse` endpoint with `Accept: text/event-stream`, matching the reference's explicit SSE negotiation. Local automatic mode selects delta text and cumulative-snapshot usage as explicit local policy. Unsupported media/parts and invalid/truncated streams fail rather than being guessed. No automatic generation request is made to test entitlement.

The installed native host passes session context headers and generation options at the request root, unlike the installed npm SDK's nested `generation` object. The driver validates and discards its known context headers: `x-opencode-session`, `x-opencode-session-id`, `x-opencode-parent-session-id`, `x-session-affinity`, `x-session-id`, `x-parent-session-id`, `user-agent`, `x-opencode-project` and `x-opencode-client`. Names are case-insensitive; duplicates, unknown names, accessors and non-printable/oversized values fail. A supplied header object must include `x-opencode-session`. None are forwarded to Google; in particular, the caller's User-Agent never overrides the fixed local CLI identity policy. Authentication headers remain rejected.

The native session builder also supplies `promptCacheKey`. This bounded printable string is validated and discarded as a cache-affinity hint for a protocol that does not implement provider-managed prompt caching. It neither enables caching nor becomes a Google session ID; an explicit `cache` policy remains unsupported. This follows the installed SDK's documented distinction between affinity and cache policy. The supported root generation aliases are `temperature`, `topP`, `maxTokens` and `stop`. Nonempty root and nested generation options cannot be mixed. Unsupported options, unknown provider metadata, media and encrypted reasoning remain rejected rather than being silently dropped.

The host also attaches an optional local `id` to each history message. The bridge validates it as 1–512 printable ASCII characters without spaces and discards it; message identity is not a remote protocol field. Tool-call/result IDs inside content parts remain preserved for correlation. Message-level metadata, provider metadata and native overrides remain unsupported.

Tool-call/result parts may carry `providerExecuted: false` for tools executed by the local host. The bridge validates that own value and omits the flag from the service history; `true` and other values remain unsupported. This does not enable provider-native execution.

The route explicitly declares `providerMetadataKey: 'offlineInference'`, matching the event/history namespace. The host selects this key when persisting and reconstructing native response metadata; falling back to the provider ID would lose thought signatures across a full session even though a direct SDK loop preserves them. A host-shaped round-trip regression covers that boundary. Failed inference HTTP responses expose only fixed status classes and the bounded recognized HTTP 429 reasons described below, never server text, destinations or causes.

The built-in context system part duplicates its rendered instructions in `metadata.experimental.instructions`, an array of `{ key, text }` records. Only that exact system-part annotation is accepted: plain own data properties, at most 256 entries, bounded keys and a combined 1 MiB key/text budget. Joining the instruction texts with two newlines must exactly equal the system part's text, as in the host renderer. The annotation is then discarded while the rendered instructions remain unchanged in `systemInstruction`. Arbitrary annotations, accessors and annotations on user parts remain rejected, as do cache hints and provider metadata on system parts.

Text Parts with `thought: true` map to native reasoning events, never visible answer text; `false` or absent maps to text events. Validated `thoughtSignature` values round-trip only through `providerMetadata.offlineInference.thoughtSignature` on assistant text/reasoning Parts. This follows the [documented Part fields](https://ai.google.dev/api/caching#Part) and the native SDK's separate reasoning events; it does not infer any particular model's remote semantics. Signed delta Parts remain distinct rather than merging opaque signatures. Cumulative snapshots track text and reasoning separately; a signature seals the exact cumulative snapshot and subsequent revisions fail closed. Reasoning and visible text share a 1 MiB UTF-8 output budget. User/system metadata and other provider-metadata namespaces remain unsupported.

Local catalog, onboarding and inference HTTP requests use a CLI-shaped `User-Agent`, defaulting to reference version `1.4.11`; `OPENCODE_AGY_CLI_VERSION` can override the version within the validation bounds (`src/configured-user-agent.ts:3-14`, `src/configured-catalog.ts:142`, `src/configured-security.ts:280`). For local mode, `localIdentity` also adds `userAgent: "antigravity"` and `requestType: "agent"` to the generation JSON envelope (`src/configured-driver.ts:36`, `src/offline-inference.ts:156-174`). These identifiers are compatibility experiments, not proof of vendor authorization or server acceptance.

Only an explicit code exchange or refresh reads the private application configuration at `$XDG_CONFIG_HOME/opencode/antigravity-oauth-client.json`, falling back to `~/.config/opencode/antigravity-oauth-client.json`. A nonempty `XDG_CONFIG_HOME` must be absolute. The file contains exactly `clientId` (the approved consumer client ID above) and `clientSecret` (35 printable non-whitespace ASCII characters). It must be a regular file of at most 4 KiB, without a final symlink; on POSIX it must belong to the current user and grant no permissions to group/others. Size/timestamp/EOF checks reject changes during reading. Missing, malformed or unsafe configuration fails closed. The runtime never inspects an AGY executable, uses binary hashes/offsets or imports saved account tokens.

The previous binary-backed loader produced a locally reproduced login failure reported as HTTP 500 by OpenCode (`stage=local_client reason=unsupported_artifact`) when the installed executable changed. It has been removed, together with its hash profiles and binary parser. The approved AGY application identity was provisioned once into the private file, without exposing its secret or copying account tokens. This is configuration provisioning, not a runtime fallback to the executable. New installations need that private application configuration; tests use synthetic configuration and exercise both code exchange and refresh with no executable, or an unrecognized executable. These checks do not establish successful live OAuth exchange or inference.

The secret is stored only in the private application configuration outside the project and added as `client_secret` in code/refresh POST forms to `https://oauth2.googleapis.com/token`, never in authorization URLs, root plugin options, credential metadata, bindings, logs or docs. OAuth waits at most five seconds for client configuration and rejects promptly when the transaction/client is cancelled. Underlying filesystem operations cannot always be interrupted; their handle and buffer cleanup still runs when they settle, and a late configuration result cannot resume a token request. The read buffer is cleared in `finally`; the form field is removed after exchange. JavaScript strings and the serialized HTTP request cannot be reliably zeroed, so this is not a guarantee of secure runtime memory erasure. No account token is stored in the application configuration. The trusted injected factory dependency `loadLocalClientSecret` remains a test seam; root JSON cannot supply a loader, path, secret or destination override.

Local loader errors have fixed messages such as `Local OAuth diagnostic: stage=local_client reason=unreadable` and `Local OAuth diagnostic: stage=local_client reason=invalid_client_configuration`. Check the private file's availability, ownership, permissions and schema without sharing its contents. No original cause or file content is exposed. Tests use synthetic application secrets under an injected transport. Installation/reload and verification of actual model metadata remain separate. A reported successful user login does not establish discovery, inference entitlement or vendor permission.

## Quota bridge for OpenCode Quota

Optional local-mode-only option. Adding `quotaBridge` to the root options of `agy-local-oauth` publishes the Antigravity quota as a `quota-v1` endpoint on loopback, which the OpenCode Quota extension can read as a Custom Provider, the way the Junie and QwenCloud plugins do:

```jsonc
{
  "package": "/caminho/absoluto/opencode-antigravity-oauth",
  "options": {
    "mode": "agy-local-oauth",
    "authorizationAcknowledged": true,
    "quotaBridge": { "port": 62369, "apiKeyEnv": "ANTIGRAVITY_QUOTA_BRIDGE_KEY", "autoKey": true, "shared": true }
  }
}
```

Registration on the consumer side is a separate step in the OpenCode Quota settings (`providers.custom`), pointing at `http://127.0.0.1:<port>/quota` with `format: "quota-v1"`, the same `apiKeyEnv` name and `enabled: true`. OpenCode Quota may add such an entry disabled; it must be enabled to appear.

- Accepted keys are exactly `port` (1-65535), `apiKeyEnv` (an environment-variable name), `autoKey` and `shared`, booleans. Anything else, including a getter, is rejected with a message that names the offending option, and `quotaBridge` is rejected in `agy-public-oauth` mode.
- `autoKey` defaults to `true`: the first lease generates a fresh 32-byte hexadecimal key, exports it as `apiKeyEnv` in the OpenCode process and restores the previous value (deleting it when there was none) when the last lease releases or the bridge cannot start. With `autoKey: false` the plugin never touches the environment; it uses an already exported key and must find 32-512 printable characters there, otherwise it reports `missing-key`/`invalid-key` and skips the bridge while OAuth and inference continue to work. An externally supplied key is only as strong as you make it: the checks bound its shape, not its entropy.
- `apiKeyEnv` may not name a process-wide variable (`PATH`, `HOME`, `NODE_OPTIONS`, `LD_PRELOAD`, `TMPDIR`, the `XDG_*` roots and similar), because exporting the key there would change resolution for the whole OpenCode process.
- Within one OpenCode process the bridge is shared by every plugin instance through a process-global lease registry (`configured-quota-bridge-state.ts` / `configured-quota-bridge-plugin.ts`), the same pattern the Junie and QwenCloud plugins use. The first instance binds the port and owns the key; later instances (other locations, reloads) acquire a lease on the same bridge and URL instead of binding again, and the bridge closes only when the last lease releases. `getQuota` tries each live lease until one resolves a real quota, so an inactive or reloading location no longer pins the bridge to a single instance's catalog state.
- With `shared: true` (requires `autoKey: true`, the same setting the Junie and QwenCloud plugins use) the election also spans processes. The token lives in a private state file (`~/.local/state/opencode-antigravity-oauth/quota-bridge-v1/bridge.key`, directory `0700`, file `0600`, published atomically so the first writer wins; `configured-quota-bridge-storage.ts`). A process that finds the port taken probes `/quota-bridge-health` with an HMAC nonce challenge (`configured-quota-bridge-shared.ts`): an owner that proves the shared token is reused instead of duplicated, and a monitor retakes the port when the owner dies, so a service restart keeps the quota visible. The health route exists only when the bridge starts with `sharedHealth`, answers `204` with a response proof, never accepts the bearer key, and is rate-limited; it reveals nothing about the quota or the token. Without `shared`, a second process that finds the port taken reports `start-failed` and does not listen.
- Enabling the bridge does not change the credential binding, so existing authorizations are not invalidated by adding or removing the option.

Each request reads only the active OAuth credential and a validated project; nothing is accepted from the caller. The project comes from the published inventory when fresh, and is otherwise discovered on demand (`loadCodeAssist`) so an expired inventory no longer forces an `Unavailable` result. The quota value comes from `POST https://daily-cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary` with exactly `{"project": "<validated project>"}` and the same fixed CLI identity as other local requests. Responses are bounded (1 MiB, 15 s), redirects are rejected and the only failure text is `Quota unavailable.`.

Percent rows come from `remainingFraction` buckets: the window becomes part of the row name, the group display name becomes the label, `resetTime` becomes `resetTimeIso` only when it parses, disabled buckets and buckets without a fraction are skipped, fractions are clamped to 0-100 percent, text is control-character-free and bounded to 80 code points, duplicate names are suffixed and at most 64 rows are emitted. When nothing is usable, a single `Unavailable` status row is returned instead, so the consumer shows an explicit state rather than fabricated numbers.

The bridge listens only on `127.0.0.1`, serves exactly `GET /quota`, requires a single `Authorization` header equal to `Bearer <key>` compared through SHA-256 with `timingSafeEqual`, pins the `Host` header to its own bound address, rejects `Origin`, `Transfer-Encoding`, a non-zero `Content-Length`, other methods and paths, caps headers and connections, answers `503` with a fixed body when the upstream fails, closes on plugin cleanup or abort and never logs the key. Results are cached briefly (5 s of data, 2 s of `Unavailable`), concurrent requests share one upstream call, and a `credential.switched` or `credential.updated` event drops that cache, so a polling quota UI cannot multiply credential-bearing requests or keep showing another account's numbers for long.

## OAuth and credential lifecycle

Authorization uses random 128-bit state, a fresh PKCE-S256 verifier, a five-minute transaction, a bounded pending set and the native `mode:'code'` callback. Google requests additionally include `access_type=offline`. Existing complete configured mode requires the full exact HTTPS callback URL including state and code; bare codes, wrong state/destination, duplicate parameters, denial and unknown parameters fail. Both explicit presets additionally accept the page's displayed code, with the returned-state limitation documented above. No listener is launched and this code never fetches the redirect destination. Completion is single-use; duplicate completion cannot cancel an already-running winning exchange. Expiration, disposal and cancellation invalidate pending exchanges.

Authorization captures the current connection selection before creating its transaction and rechecks it before and after the exchange. Refresh also snapshots/rechecks selection around its asynchronous exchange. A delayed result after a selection change fails instead of returning credentials to the host; authorization then consumes/cancels the transaction. The plugin never calls credential activation or writes secret values to `ctx.storage`. Native OpenCode owns persistence/activation after a callback returns and must retain the original transaction/credential association; the plugin does not claim an atomic lock over host operations after that return boundary.

The pinned form token exchange returns a native `Credential.OAuth` to OpenCode. Refresh is configuration-bound and single-flight for the same refresh token, preserves an omitted refresh token and returns rotation. Missing initial refresh uses the SDK-required empty string sentinel, with later refresh requiring reauthorization. No retry or alternate credential is attempted. A bounded printable opaque `id_token` is accepted and immediately discarded: never decoded, persisted, trusted as identity, or used for authentication. Other unexpected token fields fail. Access token, numeric positive integer `expires_in` and Bearer type are validated; an explicit returned scope must include every requested scope. Extra grants are discarded, never treated as identity or entitlement.

OpenCode owns storage: the registered authorize/refresh return values are persisted by the native host. Official `integration.ts` resolves expiring credentials by calling refresh and persisting the replacement before returning it. Inference always waits for `connection.resolve`; a host refresh/save failure prevents dispatch and never falls back to a prior token. Tests simulate successful persistence/rotation and save failure in memory without reading any real credential store.

Credential metadata binds the configured issuer/client/endpoints/scopes/project/policies/model IDs by hash, not by unverified account claims. Each loaded model captures its inventory's selected credential ID, and inference resolves/rechecks the matching current OAuth selection. Cached models cannot silently follow an account switch. Expired/foreign/key/env credentials fail before transport. Provider source binding prevents presenting one connection's inventory as another's entitlement.

## HTTP, cleanup and supported subset

Local-client inference defaults to CLI User-Agent version `1.5.8`; quota and catalog retain their `1.4.11` default so the inference comparison does not change those requests. The existing `OPENCODE_AGY_CLI_VERSION` override still applies to all three; absent or blank overrides use each path's default. This header update alone does not establish contextual request acceptance.

Configuration is a deeply frozen, bounded JSON snapshot. Accessors, symbols, prototype-pollution keys, sparse/oversized arrays, cycles, unknown fields and excessive depth/size fail closed. HTTP sets `redirect:'error'`, `credentials:'omit'`, `referrerPolicy:'no-referrer'`, checks status/redirect/final URL and never exposes raw remote bodies or arbitrary causes. Inference HTTP 429 may read at most 16 KiB for at most one second, with caller cancellation, only under JSON/SSE content types. A single structured Google ErrorInfo maps recognized capacity/quota/rate reasons to fixed `http_429_capacity`, `http_429_quota` or `http_429_rate` stages; a single-element error array is accepted, while malformed, ambiguous, unknown or unreadable data remains generic `http_429`. Local-client inference retries generic/rate 429 and 5xx responses before streaming, up to three attempts with the same body, request ID and credentials. Recognized quota/capacity errors and accepted streams are not retried. Retry-After milliseconds, seconds or dates override bounded backoff; a requested delay over 30 seconds terminates instead of retrying early. Caller cancellation and existing total/headers deadlines include backoff. Generic nonlocal inference and token exchange retain their previous no-retry behavior. This does not infer exhausted quota. Other inference HTTP error bodies are cancelled without reading. Token JSON is limited to 64 KiB/30 seconds; inference to 16 MiB and 1 MiB per decoded frame. Transport reads can coalesce multiple valid frames larger than 1 MiB in aggregate; the per-frame and total bounds remain enforced.

Native root `timeout` accepts a nonnegative finite number, `false`, or `{ total, headers, chunk }` with each component a nonnegative finite number or `false`. Scalars affect only `total`; zero is a deadline, not a disabled component. Policies are copied per request and never serialized to Google. Total bounds the operation including credential resolution, headers bounds the wait for the HTTP `Response`, and chunk bounds each raw body read before SSE framing. Explicit policies replace the legacy 120-second total; only absent timeout uses that legacy bound. An explicit empty policy has no deadlines. Host-injected policies normally supply 300-second headers and 900-second chunk bounds. Cancellation remains active even when every deadline is disabled, and timers/listeners are removed on completion. The optional third argument to `OfflineTransport(body, signal, options)` carries `options.timeout`; `inferOffline` enforces total, while an injected transport must implement its own headers/chunk boundaries. The configured HTTP transport implements all three.

Cancellation interrupts pending fetch/read operations even when the injected implementation ignores AbortSignal; late fetch responses are cancelled. Cleanup disposes native registrations, aborts requests/logins, removes runtime handles and invalidates cached models. The volatile runtime registry is shared between module namespaces through a versioned `globalThis[Symbol.for(...)]`, because the host can retain a provider module after reloading the local plugin namespace. A fixed versioned driver URL bypasses older retained modules; no timestamp or per-request cache busting is used. Serialized settings contain an opaque runtime handle and selected credential ID, not a token. Standard same-process file-URL loading is supported, not remote/worker model loading.

The native model resolver injects credential metadata/`apiKey` into driver settings. The driver accepts the documented shape but ignores that token option: it independently resolves native OAuth credentials each dispatch. Nonempty headers/body and arbitrary settings fail rather than overriding transport. Request IDs use the SDK-provided ID or a fresh UUID; fixed-ID offline fixtures retain their earlier mismatch rejection.

Local discovered inventories advertise text input/output and experimental tools; complete configured mode retains its text-only restrictions. Tool-call events remain buffered until a valid terminal `STOP` and complete stream; synthetic coverage does not establish live tool compatibility. Unsupported options, media and unhandled events fail explicitly. Complete configured mode keeps operator-selected text and usage semantics. Missing usage remains missing. Stream failures expose only fixed `offline_code` and `offline_stage` enums to distinguish transport, framing, response conversion, native output and native usage, never response bodies or arbitrary causes. Dynamic catalogue discovery is limited to the local preset; no quota mapping, OIDC identity or policy bypass is implemented. Full built-in coding-agent/tool compatibility is not claimed.

Native tool declarations may include an object-valued `outputSchema`, adapted to `FunctionDeclaration.responseJsonSchema`, alongside `inputSchema` mapped to `parametersJsonSchema`. The [official FunctionDeclaration contract](https://github.com/googleapis/googleapis/blob/master/google/ai/generativelanguage/v1beta/content.proto) defines this output-schema field. The advertised schema matches the existing result encoding: either an object containing only required `result` constrained by the original output schema, or an object containing only required `error` with the SDK failure value. Output constraints apply to the success value rather than incorrectly to its envelope. Schemas with `$ref`, `$id`, anchors or dynamic/recursive references are rejected rather than changing their scope by embedding them. Both schemas pass the bounded JSON serializer, rejecting accessors, invalid prototypes, excessive depth/size and non-object roots. Provider-native declarations, freeform, tool metadata and cache hints remain unsupported. Input validation failures expose only fixed stage enums (including schema/metadata/native/freeform/cache tool boundaries), never unrecognized field names or values.

`single-report` rejects any second usage object, including an identical or empty object. `cumulative-snapshot` preserves the last exact report, without summing reports, merging fields or deriving total/output counts. Every previously reported count must remain present and nondecreasing; otherwise the stream fails with `native_usage`, without finish events or releasing buffered tools. New fields and explicit zero are retained. This acceptance rule is deliberately conservative: the [official GenerateContentResponse.UsageMetadata contract](https://github.com/googleapis/googleapis/blob/master/google/ai/generativelanguage/v1beta/generative_service.proto) describes request/candidate totals, not per-chunk deltas, but does not guarantee monotonicity for the Antigravity endpoint. The final snapshot alone maps promptTokenCount/totalTokenCount to inputTokens/totalTokens; all reported fields remain in providerMetadata.offlineInference, and missing counts stay absent.

No `enabledCreditTypes`, credit fallback, billing or purchase requests are emitted. Conditional free-tier onboarding is the state-changing exception described above; it is not proof of a subscription or entitlement. There is no API-key/ACP substitution. `cost: []` means absent/unknown tariff metadata, not free service or zero monetary cost. Complete configured mode retains operator-supplied catalogue/limits; local mode uses returned metadata or the explicitly estimated static fallback. OAuth and model visibility do not establish subscription ownership or inference entitlement.
